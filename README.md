# FPGA-Based-VGA-Command-controlled-Instrument
FPGA-Based VGA Instrument Monitoring System

## 1. Project Introduction

The FPGA-Based VGA Instrument Monitoring System is a VLSI mini project developed using Verilog HDL and Quartus II software for the Cyclone II FPGA development board (EP2C8T144C8).

The system creates a real-time graphical monitoring interface for laboratory instruments and industrial systems. It reads the status of onboard switches, identifies the selected operating mode, and displays the corresponding information on a VGA monitor.

The design combines digital control logic, clock division, VGA synchronization, pixel-coordinate generation, graphical rendering, and LED status indication in a single FPGA-based system.

## 2. Project Objectives

- To design a real-time monitoring interface using Verilog HDL.
- To implement the system on the Cyclone II EP2C8T144C8 FPGA.
- To generate VGA timing signals for a 640 × 480 display.
- To implement four selectable operating modes.
- To display a colour-coded graphical dashboard.
- To indicate the selected operating mode using onboard LEDs.
- To visualize the status of eight switches.
- To achieve standalone operation without UART, RS-232, or PC commands.

## 3. Problem Statement

Laboratory instruments and industrial systems require a clear visual interface to indicate their current operating modes and status. Monitoring systems should provide easily understandable visual feedback about operating conditions.

This project implements a low-cost, standalone graphical monitoring interface using an FPGA development board. The FPGA performs mode selection, VGA timing generation, graphical rendering, and LED control without depending on an external computer to generate the display.

## 4. Proposed Solution

The proposed system uses onboard switches as inputs and a VGA monitor as the primary visual output.

The FPGA reads SW1 and SW0 to select one of four operating modes. A mode decoder determines the corresponding display colour and LED indication. The VGA controller continuously generates the synchronization signals and pixel information required to display the dashboard.

An eight-cell status bar represents the states of SW0 through SW7. Each cell changes colour according to its corresponding switch state, providing a simple graphical representation of the digital inputs.

## 5. System Architecture

The system consists of the following functional blocks:

### Clock Divider

The FPGA board provides a 50 MHz clock. The clock divider generates the 25 MHz pixel clock required by the VGA timing logic.

### VGA Timing Generator

The VGA timing generator produces horizontal synchronization (HSYNC) and vertical synchronization (VSYNC) signals to control the display scanning process.

### Horizontal and Vertical Counters

The counters track the current pixel coordinates on the screen. These coordinates determine which graphical element should be drawn at each pixel position.

### Mode Decoder

The mode decoder reads SW1 and SW0 and identifies the selected operating mode: IDLE, RUN, CALIBRATION, or DIAGNOSTIC.

### Dashboard Generator

The dashboard generator compares pixel coordinates with predefined screen boundaries and produces the required colours for the background, border, header, mode indicator, and switch-status bar.

### LED Controller

The LED controller provides a hardware indication of the selected operating mode. The LED output changes according to the mode-selection inputs.

## 6. Operating Modes

The system supports four operating modes selected using SW1 and SW0.

| SW1 | SW0 | Operating Mode | Indicator Colour | Active LED |
|---|---|---|---|---|
| 0 | 0 | IDLE | Blue | LED0 |
| 0 | 1 | RUN | Green | LED1 |
| 1 | 0 | CALIBRATION | Orange | LED2 |
| 1 | 1 | DIAGNOSTIC | Magenta | LED3 |

Each mode uses a distinct colour to make the current operating state easy to identify.

The LED outputs are active-low, meaning that the selected LED is activated by driving its output LOW.

## 7. VGA Display Design

The system generates a graphical dashboard with a resolution of 640 × 480 pixels and an approximate refresh rate of 60 Hz.

The dashboard includes:

- **Background:** Dark navy background.
- **White border:** Frames the dashboard.
- **Header banner:** Provides a designated header area.
- **Mode indicator box:** Changes colour according to the selected operating mode.
- **Switch-status bar:** Displays the states of all eight onboard switches.

The graphical elements are generated by comparing the horizontal and vertical pixel coordinates with predefined display regions. This coordinate-based approach generates the dashboard using FPGA logic without requiring a large image memory.

## 8. Switch Status Visualization

The design displays eight rectangular cells in a horizontal status bar, with one cell corresponding to each switch from SW0 to SW7.

- Switch ON: Green cell.
- Switch OFF: Dark-grey cell.
- Black separator lines distinguish adjacent cells.
- The status display updates when the switch inputs change.

This feature provides a convenient visual representation of the current digital input conditions.

## 9. VGA Timing Specifications

| Parameter | Specification |
|---|---|
| Input clock | 50 MHz |
| Pixel clock | 25 MHz |
| Pixel clock period | 40 ns |
| Display resolution | 640 × 480 pixels |
| Horizontal total | 800 pixel periods |
| Vertical total | 525 lines |
| Refresh rate | Approximately 60 Hz |
| Synchronization signals | HSYNC and VSYNC |

The horizontal and vertical counters define the active display area and synchronization intervals. The pixel-generation logic determines the displayed colour based on the current pixel coordinates.

## 10. Hardware Implementation

The project targets the FC-01 Cyclone II FPGA development board with the EP2C8T144C8 FPGA device.

The implementation uses the FPGA's internal logic elements, registers, counters, and I/O pins.

The main hardware interfaces are:

- 50 MHz onboard clock.
- Active-low reset input.
- Eight slide-switch inputs.
- LED output indicators.
- VGA synchronization and colour outputs.

The FPGA performs the display-control operations directly, without requiring an external processor for mode decoding or graphical rendering.

## 11. Design and Development Flow

1. Define the system requirements and operating modes.
2. Develop the Verilog HDL design.
3. Create the project in Quartus II.
4. Select the Cyclone II EP2C8T144C8 target device.
5. Configure the FPGA pin assignments according to the actual board pinout.
6. Compile the design and check for errors.
7. Simulate the control logic using ModelSim, if available.
8. Program the FPGA board.
9. Connect the VGA output to a compatible monitor.
10. Change the switches and verify the display colours and LED outputs.

## 12. Simulation and Verification

The mode-selection logic can be verified by applying all four combinations of SW1 and SW0.

| SW1:SW0 | Expected Mode | Expected Colour | Expected LED |
|---|---|---|---|
| 00 | IDLE | Blue | LED0 |
| 01 | RUN | Green | LED1 |
| 10 | CALIBRATION | Orange | LED2 |
| 11 | DIAGNOSTIC | Magenta | LED3 |

The reset signal should be applied according to the active-low reset behaviour. The switch combinations can then be changed to verify the corresponding mode and outputs.

Verification should confirm that the mode-selection logic, LED indication, and graphical colour selection operate consistently. VGA synchronization signals should also be checked against the intended timing parameters.

## 13. Advantages

- Provides real-time visual feedback.
- Implements graphical rendering directly in FPGA hardware.
- Supports four operating modes with distinct colours.
- Displays eight switch states simultaneously.
- Combines VGA output and LED indication.
- Uses coordinate-based graphics generation.
- Demonstrates practical FPGA and digital-system design.
- Operates independently without PC commands or serial communication.

## 14. Applications

Potential applications include:

- Laboratory instrument monitoring interfaces.
- Industrial equipment status panels.
- Digital control-system demonstrations.
- FPGA development board testing.
- Hardware debugging and status indication.
- Educational demonstrations of VGA interfacing.
- Digital system status visualization.

Real instrument monitoring would require appropriate sensor or instrument-status inputs.

## 15. Limitations

- Limited to a 640 × 480 display resolution.
- Requires a compatible FPGA board and VGA monitor.
- The current design uses switches rather than real instrument sensors.
- Complex graphics may require additional FPGA resources.
- Text rendering requires additional character-generation logic.
- The current implementation provides basic status visualization rather than complete instrument control.

## 16. Future Enhancements

The system can be enhanced with the following features:

- Add text labels for IDLE, RUN, CALIBRATION, and DIAGNOSTIC modes.
- Integrate sensor inputs for real-world instrument monitoring.
- Add warning and fault-status indicators.
- Display numerical measurements and operating parameters.
- Introduce configurable monitoring thresholds.
- Expand the dashboard with additional graphical elements.
- Add communication or data-logging features in future versions.

## 17. Conclusion

The FPGA-Based VGA Instrument Monitoring System demonstrates the implementation of a real-time graphical interface using Verilog HDL and the Cyclone II FPGA. By integrating mode decoding, VGA timing generation, coordinate-based graphics, switch-status visualization, and LED indication, the system provides a simple standalone dashboard for displaying digital operating states.

The project demonstrates the practical application of FPGA-based digital design, synchronous counters, control logic, and VGA interfacing. It also provides a foundation for future enhancements involving real instrument measurements, fault detection, and advanced visual monitoring.
